# H.264 vs H.265 比較

## H.265（HEVC）実装完了！

### 設定方法

```bash
# H.265を有効にして起動
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d
```

### 実測データ

| 項目 | H.264 (h264_nvenc) | H.265 (hevc_nvenc) |
|-----|-------------------|-------------------|
| エンコーダー | h264_nvenc | hevc_nvenc |
| GPUメモリ使用量 | 272MB | 330MB |
| セグメントサイズ | 約2.4MB | 約2.5MB |
| 電力消費 | 105W | 105W |
| CPU使用率 | 10-12% | 10-12% |

### H.265の利点

1. **圧縮効率**
   - 同じ品質でファイルサイズを約25-50%削減
   - 同じビットレートでより高画質

2. **帯域幅節約**
   - モバイル回線での視聴に有利
   - サーバー帯域幅コスト削減

3. **将来性**
   - 4K/8K対応
   - 最新デバイスで標準サポート

### H.264の利点

1. **互換性**
   - 古いデバイスでも再生可能
   - 幅広いブラウザサポート

2. **エンコード速度**
   - わずかに高速（差は僅か）

### 切り替え方法

```bash
# H.264に戻す場合
docker compose -f docker-compose.yml -f docker-compose.gpu.yml down
docker compose -f docker-compose.yml -f docker-compose.gpu.yml \
  run -e USE_HEVC=false backend

# H.265にする場合（現在の設定）
docker compose -f docker-compose.yml -f docker-compose.gpu.yml \
  run -e USE_HEVC=true backend
```

### パフォーマンス比較

#### GPU使用率（リアルタイム）
```bash
nvidia-smi dmon -s pucvmet -c 10
```

#### エンコード品質
- H.265: 同じCQ値でより高画質
- H.264: より広い互換性

### 推奨設定

- **新しいデバイス**: H.265（現在の設定）
- **古いデバイス対応**: H.264
- **帯域幅制限環境**: H.265
