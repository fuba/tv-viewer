# eMudhra CA対策を通常ビルドに維持する

2026-10-23。稼働中イメージへの緊急対処に加え、通常のビルド・再配備でも古い信頼情報が戻らないようにした。

Dockerの各ステージで依存取得の前と最終成果物に、指紋一致のCAだけを除去する。既存の独自CAと実行ユーザーは保持する。ビルド用の静的Goツールは実行後に自身を削除する。Javaが含まれる場合は既存のSHA-256ブロックリストを保ち、漏洩証明書の指紋を追加する。

Node、Go、uvの指定は該当する修正版へ更新した。Pythonを使用する定義ではcertifi 2026.10.19以降を要求し、既存の固定ファイルでは他のパッケージの版を維持した。Composeの外部イメージにも必要に応じてCA対策を行うビルドを設定し、ブラウザ参照は対策済みビルドのダイジェストに固定した。変更が存在する項目に限る。

検証：変更したDockerfileのCA対策ステージを実ビルドし、Pythonの固定ファイルはuvの整合性検査を実施した。重いGPUアプリのモデル全体の再取得は行っていない。アプリ本体を含む通常ビルドと実TLS接続はBBA・Feed Reader・fuba-browserで確認した。対象外のリポジトリまでアプリ全体を再ビルドしたという意味ではない。

Goの対象モジュール：`backend`。テスト用PostgreSQLや画像変換ツールなど、必要な実依存を用意して検証した。

根拠：[Mozilla incident](https://bugzilla.mozilla.org/show_bug.cgi?id=2083449)、[対応状況と検証サイト](https://emudhra.we-have-a-problem.com/)。
